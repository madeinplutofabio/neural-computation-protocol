# NCP trace pretty-printer

Read one per-call JSONL trace and print its invocation timeline and summary
using Python 3.10+ and only the standard library.

From the repository root:

```sh
python3 tools/trace_pretty.py /path/to/trace.jsonl
```

The runtime emits a `runtime_info` header and an `invoke` record for each
brick invocation (schema `ncp-trace-0.1`). See
[trace.rs](../../runtime/src/trace.rs) and
[the NCP specification, section 11](../../spec/ncp-v0.2.3.md#11-observability-and-tracing).

The tool lists invocations in file order. It excludes the header and counts
unknown record types separately, following the SDK's forward-compatible
handling of record types within the supported schema. It validates the
fields used for the timeline, not the complete protocol or trace integrity.
Blank lines are skipped. Empty traces, unreadable files, invalid JSON,
unsupported schema versions, invalid timeline fields and mixed trace IDs
produce an error on stderr and a nonzero exit code without a partial report.
A valid trace containing a Failure result is still readable and exits zero.

Total latency is the sum of invocation latencies, not necessarily elapsed
wall-clock time. Values are displayed to three decimal places.

## Real echo-pipeline example

Use the official NCP v0.4.0 CLI (or build the current runtime) from the
repository root:

```sh
ncp run examples/graphs/echo-pipeline/graph.yaml \
  --input examples/graphs/echo-pipeline/sample.json \
  --brick-dir examples/bricks --trace echo.jsonl
python3 tools/trace_pretty.py echo.jsonl
```

The following output was obtained from a real execution of the official
v0.4.0 Linux x86_64 release against the echo-pipeline graph at source commit
`b767303c21843e63ac464e5d8f3f22f947ced44f`:

```text
step | node_id   | brick_id              | result_type | latency_ms
-----+-----------+-----------------------+-------------+-----------
   0 | echo_node | org.ncp-examples.echo | Success     |      0.213
Total steps: 1
Total latency (sum of invokes): 0.213 ms
Results by type:
  Success: 1
```

Latency varies between executions. The trace can also be generated by
`ncp-mcp-server --trace-dir` using the
[echo-pipeline MCP smoke recipe](../../examples/mcp/echo-pipeline-mcp-smoke.md).

## Tests

```sh
python3 -m unittest discover -s tools/trace-pretty -v
```

Tests exercise the CLI using synthetic records and require no network,
models, Rust build or third-party Python packages. Real-time tailing, HTML
rendering and cross-trace aggregation are outside the scope of this tool.
